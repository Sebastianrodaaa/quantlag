## 2026-11-02 afternoon (2): quantlag (unbiased export of RL policy updates into int8 and 4-bit CPU rollout copies)

Rule: no GPU spend. Everything below runs on CPU (or HF ZeroGPU free tier if a Space is wanted for the demo only).

Repo name: quantlag
GitHub topics: ai-frontier-research, reinforcement-learning, grpo, quantization, stochastic-rounding, training-inference-mismatch, cpu-inference

Signal: rl-train-infer-mismatch (0.4): bf16 Rounding Silently Discards Most RL Policy Updates / Fair Cast (https://arxiv.org/abs/2610.41073v1), InterQ-RL (https://arxiv.org/abs/2610.35303v1), On the Origin and Evolution of Training-Inference Mismatch (https://huggingface.co/papers/2610.40945).

Idea: cheap RL on CPU means rollouts come from an int8 or 4-bit group-quantized copy of the policy, re-quantized from fp32 master weights at every sync. Integer grids are far coarser than bf16, so with round-to-nearest almost every per-step update is smaller than half a quantization step and is thrown away: the policy that generates data stops moving. quantlag exports the master into the quantized grid with an unbiased rule (stochastic rounding, or error feedback that carries each weight's rounding residual into the next sync) with the quantization scales frozen between scale refreshes, and computes the training loss against the served quantized copy.

Why it is new (closest prior work, checked on arXiv, GitHub and HF on 2026-11-02):
- Fair Cast (https://arxiv.org/abs/2610.41073v1): the same lag for bf16 exports, fixed with unbiased rounding; GPU, bf16 only, no integer grids or per-group scales.
- QuRL (https://arxiv.org/abs/2602.13953v1): names the same weight update problem for INT8/FP8 rollouts and fixes it with invariant scaling (and adaptive clipping); not unbiased rounding or error feedback, not 4-bit, GPU.
- QaRL (https://arxiv.org/abs/2604.07853v1), InterQ-RL (https://arxiv.org/abs/2610.35303v1), QeRL (https://arxiv.org/abs/2510.11696v1): align or correct the quantized behavior policy at the loss; they do not change how updates are exported, so a stalled served policy stays stalled.
- arXiv searches (stochastic rounding + int8 + rollout, quantized + rollout + stochastic rounding, error feedback + rollout) returned nothing beyond Fair Cast; GitHub searches (stochastic rounding rl rollout, int8 rollout grpo cpu) returned 0 repos.
- Honest scope: the novelty is the transfer of unbiased export to integer grids with frozen scales, the direct comparison against QuRL's invariant scaling, and doing it on CPU. It is narrow, and the README must say so.

Hypothesis (falsifiable): with Qwen2.5-0.5B-Instruct and an int8 per-channel or 4-bit (group 32) served copy, round-to-nearest export changes under 1% of served weights per step after the first steps, while error-feedback export makes the served copy track the master (served vs master KL on held-out prompts at least 5x lower at step 50), and GRPO with error-feedback export reaches a higher held-out GSM8K accuracy than round-to-nearest at the same step count. Fails if the served-weight change rate under round-to-nearest is not small (no lag to fix), if the KL gap is under 2x, if the accuracy difference is within 3-seed variance, or if QuRL-style invariant scaling matches error feedback (then report that).
